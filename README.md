# fobj

Evolve images with CPPN-NEAT and MAP-Elites. Each niche is a text label, and
[CLIP](https://github.com/mlfoundations/open_clip) decides how well an image
fits it. By default the niches are the 1000 ImageNet classes, named from
their WordNet synsets.

This is a modernised version of the original "fooling objects" code. That
code used MultiNEAT and a Caffe GoogLeNet and is kept under [`legacy/`](legacy/)
for reference. The 2D image path has been ported so far. The 3D voxel path
has not been ported yet.

## How it works

* **Genomes**: [neat-python](https://github.com/CodeReclaimers/neat-python)
  genomes, configured by `fobj/data/cppn2d.cfg`. MAP-Elites only mutates
  them; there is no crossover and no speciation.
* **CPPN evaluation**: `fobj/pytorch_neat/` is a trimmed and fixed copy of
  Uber's [PyTorch-NEAT](https://github.com/uber-research/PyTorch-NEAT) CPPN
  code (Apache-2.0). It evaluates a genome over the whole pixel grid in one
  pass. A test checks that it matches `neat.nn.FeedForwardNetwork` for every
  neat-python activation and aggregation. Fixes relative to upstream:
  * a node with no inputs now returns `activation(bias)`, not its raw bias
  * `sin` is now `sin(5x)` and `gauss` is clamped, both as in neat-python
  * the `product` aggregation works; upstream named it `prod`, so any genome
    that used it raised a KeyError
  * added the activations and aggregations upstream was missing
  * tensors are created on the right device and dtype
  * nodes are evaluated in order instead of by recursion
  * works with neat-python 2.x
* **Rendering** (`fobj/render.py`): the CPPN inputs are `(x, y, d)` in
  [-1, 1], where `d` is the distance from the centre. The outputs are RGB,
  squashed to [0, 1] with a sigmoid.
* **Scoring** (`fobj/clip_eval.py`): each niche name goes into one or more
  prompt templates (default `"a photo of a {}."`). The resulting text
  embeddings are averaged per niche and cached in `~/.cache/fobj`. An image
  scores against every niche at once, in one of two modes:
  * `softmax` (the default) is CLIP's zero-shot probability. It plays the
    role of the old classifier confidence.
  * `cosine` is the raw similarity.
* **MAP-Elites** (`fobj/map_elites.py`): a port of `legacy/melites.py`.
  Every child competes in all niches. Children are generated and scored in
  batches. `--curiosity` turns on the old `--map_opt` parent-selection
  heuristic.
* **Niches** (`fobj/niches.py`, `fobj/data/imagenet_wordnet.tsv`): the 1000
  ILSVRC WordNet ids mapped to synset lemmas, generated by
  `scripts/make_imagenet_niches.py`. The two names that collide get their
  hypernym added: `crane (wading bird)` / `crane (lifting device)` and
  `maillot (tights)` / `maillot (swimsuit)`. You can also pass
  `--niches my_labels.txt`, with one label per line.

## Usage

```bash
pip install -e .            # or: pip install -e '.[dev]' for pytest

# 100k evaluations, 1000 ImageNet/WordNet niches, ViT-B/32 CLIP
fobj run --out runs/imagenet --evals 100000 --seed 1

# resume, then render the elites at 512px
fobj run --out runs/imagenet --resume runs/imagenet/checkpoint.pkl --evals 200000
fobj export runs/imagenet/checkpoint.pkl --size 512 --top 100
```

`fobj run` writes the following to `--out`:

* `checkpoint.pkl`: the archive, the niche names and the NEAT config
* `top.png`: a contact sheet of the best elites
* `run.json` and `cppn.cfg`: the settings and NEAT config used for the run

Useful flags:

| flag | default | meaning |
| --- | --- | --- |
| `--clip-model` / `--clip-pretrained` | `ViT-B-32-quickgelu` / `openai` | any `open_clip.list_pretrained()` pair, e.g. `ViT-L-14` / `datacomp_xl_s13b_b90k` |
| `--prompt` | `"a photo of a {}."` | repeat the flag to average several templates |
| `--score` | `softmax` | `softmax` (niches compete) or `cosine` |
| `--niches` | `imagenet` | or a text file of labels |
| `--batch-size` | 64 | images per CLIP forward pass |
| `--seed-evals` | 500 | random genomes before elites are mutated |
| `--curiosity` | off | old `--map_opt` parent selection |
| `--device` | `auto` | `cuda`, `mps` or `cpu` |

On a 4-core CPU with ViT-B/32 this runs at about 30 evaluations per second.
CLIP takes almost all of that time; rendering a 224² CPPN takes about 2 ms,
so a GPU should be much faster.
